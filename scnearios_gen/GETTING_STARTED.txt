🚀 QUICK START - 3 WAYS TO USE
─────────────────────────────────────────────────────────────────────────────

1️⃣  COMMAND LINE (Fastest)
   ────────────────────────────────────────────────────────────────────────
   python k8s_cluster_generator_enhanced.py \
     --nodes 20 \
     --use-case microservices \
     --topology-type hub_spoke \
     --output my_cluster.json


2️⃣  YAML CONFIG (Most Flexible)
   ────────────────────────────────────────────────────────────────────────
   # Edit example_cluster_config.yaml, then:
   python k8s_cluster_generator_enhanced.py \
     --config example_cluster_config.yaml \
     --output my_cluster.json


3️⃣  PYTHON SCRIPT (Most Control)
   ────────────────────────────────────────────────────────────────────────
   from k8s_cluster_generator_enhanced import *
   
   config = ClusterDynamicConfig(
       num_nodes=20,
       use_case=UseCase.MICROSERVICES,
       subnet_config=SubnetConfig(
           subnet_ranges=[1, (2,4), (3,6)],
           subnet_labels={1: "dmz", 2: "app", 3: "db"}
       ),
       network_topology=NetworkTopologyConfig(
           topology_type="hub_spoke"
       )
   )
   
   generator = EnhancedK8sClusterGenerator(config)
   result = generator.generate()

✨ KEY FEATURES
─────────────────────────────────────────────────────────────────────────────

  🔧 Dynamic Subnet Configuration
     • Define subnets with ranges: [1, (1,4), (2,6)]
     • Label subnets for better organization
     • Set sensitive data probabilities per subnet

  🌐 Network Topology Control
     • Predefined: mesh, star, hub_spoke, random
     • Custom adjacency matrices
     • Fine-grained connectivity control

  📦 Service Distribution
     • Multiple strategies: probability, required, graph_theory_random
     • Service-to-subnet affinity mapping
     • Required and excluded service lists

  🔒 Firewall Configuration
     • Policies: _all, _none, _subnets
     • Per-service exceptions
     • Random blocking simulation

  👁️  OSINT Visibility
     • Control what external attackers can discover
     • Service visibility strategies
     • Simulate reconnaissance

💡 TIPS & TRICKS
─────────────────────────────────────────────────────────────────────────────

  1. Always use --seed for reproducible configurations
     Example: --seed 42

  2. Start with example_cluster_config.yaml and modify it
     It has comprehensive comments and examples

  3. Use --verbose to see detailed generation information
     Great for debugging and understanding the process

  4. Generate multiple scenarios at once with --count
     Example: --count 10 creates 10 variations

  5. Combine with other tools for complete attack graphs
     Works with network topology generator and vuln assignment

📖 COMMAND LINE REFERENCE
─────────────────────────────────────────────────────────────────────────────

  python k8s_cluster_generator_enhanced.py [OPTIONS]

  Required (pick one):
    --config FILE              Load configuration from YAML file
    --nodes N --use-case TYPE  Specify inline

  Optional:
    --topology-type TYPE       Network topology (mesh/star/hub_spoke/random)
    --service-strategy TYPE    Service selection strategy
    --seed NUMBER              Random seed for reproducibility
    --count N                  Generate N configurations
    --output FILE              Save to JSON file
    --verbose, -v              Show detailed information
    --help                     Show all options
